前置概念

術語說明
hrList由 parameter.ini 解析而來的參數陣列，每筆為 HRItem（含 address、data、name、unit 等欄位）
paraList比對用的第二份資料清單（showPara 模式使用）
dataRead本次「讀取參數」從裝置取回的 {address, data} 陣列快照
busy讀寫進行中的旗標，防止並發操作
retryOp(3, fn)最多重試 3 次，每次失敗間隔 15ms
UART 模式直接 USB-Serial 連線；SIG（位址 0x0000~0x0003）由裝置保護，不可透過 UART 寫入
CAN 模式透過 Tool_R 轉接器；所有位址皆可寫入
Save 指令寫入位址 0x0555=1，裝置將 RAM 參數存入 Flash；讀回 0x0555=0 確認成功

步驟說明

#步驟說明協議
1前置檢查序列埠未開啟 → alert 退出；hrList 為空 → alert 退出；busy 旗標為 true → 直接返回兩者
2初始化狀態busy=true、清空 dataRead 與 failed 陣列、進度條歸零兩者
3逐一讀取依 hrList 順序，對每個 HRItem 呼叫對應協議的讀取函式兩者
4UART 讀取readUartParam(addr)：clearBuffer → write(buildUartRead) → readUartFrame(1000ms) → parseUartResponse → 驗證功能碼 0x03 且位址回音 = 請求位址（不符視為殘留回應，再讀最多 3 筆，每筆 200ms）→ 回傳 data 或 nullUART
5CAN 讀取readCanParam(addr)：clearBuffer → write(buildCanRead) → sleep(10ms) → readCanFrame(1000ms) → parseCanResponse → 驗證 ID=0x01005020、功能碼 0x03、位址回音 = 請求位址（不符則略過再讀）→ 回傳 data[4]<<8|data[5] 或 nullCAN
6重試機制每個位址最多重試 3 次，失敗間隔 15ms（retryOp）兩者
7更新資料成功 → 寫入 hrList[i].data（或 paraList）+ 推入 dataRead；失敗 → 加入 failed[]兩者
8中止條件累計失敗 ≥ 10 個位址時自動中止，防止卡死兩者
9刷新 UI更新所有參數顯示、SIG/SN 欄位、資料來源標示兩者
10結束busy=false，恢復按鈕可用；log 顯示完成訊息或失敗位址清單兩者

寫入參數流程

對應 app.js 第 419～551 行，btnWrite 事件處理。

寫入前會執行 SIG 預驗證。若裝置 SIG 與本機不符，將中止寫入，保護裝置避免載入錯誤韌體的參數。

步驟說明

#步驟說明協議
1前置檢查同讀取流程，busy 時直接 return兩者
2SIG 預驗證讀取裝置 hrList[0..3].address 的值，解碼為 8 字元 SIG 字串，與本機 SIG 比對；任一步失敗則中止兩者
3確認寫入來源UART 從 index=4 開始（跳過 SIG0~3）；CAN 從 index=0 開始（可寫 SIG）兩者
4showPara 衝突處理showPara 模式且 paraList 與 hrList 數量不符時，彈出 confirm 讓使用者選擇寫入來源兩者
5過濾清單排除 production=True 的參數（生產序號）；排除 address ≤ 0x0020 的系統保護位址兩者
6UART 寫入writeUartParam(addr, data)：clearBuffer → write(buildUartWrite) → readUartFrame(1000ms) → parseUartResponse → 驗證功能碼 0x06/0x86 且位址回音相同（不符則再讀）→ 0x86 或回填值 ≠ 寫入值 → false（不重試）UART
7CAN 寫入writeCanParam(addr, data)：clearBuffer → write(buildCanWrite) → sleep(10ms) → readCanFrame(1000ms) → parseCanResponse → 驗證 ID=0x01005020、data[1]=0x06、位址回音 data[2..3] 相同（0x86 錯誤幀位址在 data[3..4]）→ 回填值 data[4..5] 須 = 寫入值CAN
8逐筆 log每個參數寫入後記錄：[ADDR] 參數名 = 值 ✓/✗，失敗時附原因（逾時、0x86 拒絕、回填值不符）兩者
9中止條件累計失敗 ≥ 10 個位址時自動中止兩者
10失敗確認有任何地址寫入失敗時，先 confirm 是否仍要 SAVE，避免把不完整的參數組存進 Flash兩者
11Save 指令runFlashCommand(1)：寫入 addr=0x0555, data=1（回應須位址相符、非 0x86）→ 每 200ms 輪詢 0x0555，最多 5s：0 = 成功、1/2 = 進行中、其他非零 = 失敗；無回應判失敗。CAN 存檔成功後再以 runFlashCommand(2) 重載 Flash → RAM兩者
12結束進度條歸零，log 寫入結果，busy=false兩者

回應 RX（parseUartResponse）

格式相同 12 bytes；Byte 2 = 功能碼（0x03/0x06，錯誤時為 0x83/0x86），Byte 4~5 = 位址回音（錯誤時照回）；CRC 驗證通過後取 Byte[6]<<8|Byte[7] 為資料值。呼叫端以功能碼與位址回音判斷是否為本次請求的回應。

CRC 計算

項目說明
演算法簡單加總：sum = Σ bytes[1..7]（16-bit 截斷）
儲存Little-Endian：crc_Lo = crc & 0xFF，crc_Hi = crc >> 8
範圍Byte 1 ~ Byte 7（共 7 個 byte）

回應 RX 解析（parseCanResponse）

項目說明
有效 ID（讀/寫回應）0x01005020（LE）
成功讀取data[1] = 0x03 且位址 (data[2] << 8) | data[3] = 請求位址；資料值 = (data[4] << 8) | data[5]
成功寫入data[1] = 0x06、位址相同，且回填值 data[4..5] = 寫入值（韌體回填實際生效值，可抓出截斷）
錯誤碼 0x83讀取失敗（位址不存在）
錯誤碼 0x86寫入失敗；錯誤幀 data[2] = 例外碼、位址在 data[3..4]
CAN 模式每次 TX 後需等待 10ms（sleep(10)）再讀取回應，留出 Tool_R 轉接器處理時間。

重試機制 retryOp

對應 app.js 第 596～608 行。

  retryOp(maxRetries=3, fn)

    for i = 0 → maxRetries-1
      │
      ▼
    try { result = await fn() }
      │
      ├── result ≠ null 且 ≠ false → return result（成功）
      │
      └── result = null / false → continue retry
             │
             sleep(15ms)
             │
    (所有重試均失敗)
      │
      ▼
    return null
項目說明
重試次數最多 3 次（maxRetries=3）
重試間隔15ms（sleep(15)）
停止條件成功（回傳非 null/false）或 3 次全失敗
全部失敗回傳null，呼叫端記入 failed 陣列
